# Register 角色分析與原位操作

目前由手動／官方角色入口共用 view model、renderer 與 controller。Register 支援桌面及手機，保留五槽、共同尺度與唯一原位分析宿主；不再是僅限 Desktop 的唯讀預覽。

空槽／缺資料优先定位補資料；未知模型不做改善排名。完整且可計分時，weakestPositions 僅指出模型中最低貢獻位置，不表示實戰最弱或刷取收益最高。手動配置可編輯；官方配置由更新資料入口補齊。候選、方案及比較見 [候選契約](role-candidate-selection.md)、[比較範圍](decision-first-compare.md)。

## 模块与连续工作面

| 模块／DOM | 职责 |
| --- | --- |
| `js/role-register-mode.js` | 在舊初始化前判斷 Register／Classic presentation |
| `js/role-register-page.js` | 从 `mcData.role` 按实例 `roleid` 读取，呼叫同一個 adapter／renderer，編排選取、模型、草稿、返回及資料變更事件 |
| `js/role-register-renderer.js` | 无 DOM／存储依赖的 HTML 生成器；输出已用翻译 key 清单 |
| `.rr-identity` | 左侧身份锚点、角色图像、存档配置说明 |
| `.rr-loadout` / `.rr-slot` | 五个固定位置的装备卡片，独立背景和细边框；普通网格配合文本量测对齐读数 |
| `.rr-rail` | 已知副词条累计，明确排除角色、武器、主词条；不伪装完整角色面板 |
| `.rr-evaluation` | 整体评分与集中问题摘要，明确最低贡献不是替换建议 |
| `.rr-inline-analysis` | 五槽之後唯一原位宿主，連接所選槽位、候選及比較 |
| `.rr-conditions` | 实际模型条件、已知贡献小计与整套效率校正 |
| `css/role-register.css` | 根节点作用域内的连续工作面、对齐与换行规则 |

手动与导入记录只在 1A adapter 中解析不同的旧字段；两个 HTML 入口加载相同渲染模块。
renderer 不读取 `.mc-cost-list` 或旧 DOM。原 DOM 保留在未启用预览时使用；预览时隐藏并跳过旧 `mccost.js`／`mccost2.js` ready 回调及维护弹窗。
仍使用 `base.js` 中的目录和评分 API，并加载原 jQuery／Bootstrap 依赖；这不是全站去依赖改造。

## 数据与边界

- 五槽严格使用 `model.slots` 原顺序，不按 Cost 或得分排序。
- 每槽贡献条统一使用 `(value - scale.min) / (scale.max - scale.min)`。该尺度是角色总评分贡献，不是每颗独立满分 100 的质量分；上限由 1A 决定，至少为 100。
- 读数来自重新计算的 view model，忽略存档缓存得分；不引入 prototype 数值。
- `model.parameters` 新增生效模式、适用角色的额外效率和参考生命，用现有模型默认值与边界生成语言中立元数据，不变更公式。
- 空槽保留空间和位置，显示空槽／缺少数据；缺失数值为破折号。配置不完整时不补零、不选最低贡献槽、不作替换建议。
- 未知模型显示无法判断与本地化问题；已知副词条仍可累计，但注明范围。
- 已有完整三语实体名称使用 `characters.*`／`echoes.*`。缺少实体翻译時使用既有相容 fallback，保留使用者自訂名稱與原始資料；不把顯示文案寫回計算輸入。
- 全角色圖片由 CharacterPortraits 與正式資源維護；缺圖保留文字身份與數值，詳見 character-images.md。

## 状态与身份

`js/role-register-controller.js` 是无 DOM、无存储依赖的共用控制器。手动与导入角色使用同一实现。

```js
{
  selection: {
    position: 3,
    echoIdentity: 'instance:602',
    kind: 'echo'
  },
  identities: { 1: 'instance:600', 2: 'instance:601', 3: 'instance:602' },
  notice: null,
  evidenceOpen: false,
  modelChanged: false
}
```

- 正常身份使用唯一 `costId`，同时记录逻辑槽位 `position`，不根据名字、图片、DOM 顺序或 Cost 排序判断身份。
- 缺失、空字符串、无效或重复 ID 使用源对象的 `WeakMap` 临时身份 `session:*`。仅在当前载入期间可保持选择；外部刷新后不恢复此身份，也不提供可能编辑错对象的链接。
- 空槽状态为 `{position, echoIdentity:null, kind:'empty'}`，不生成假声骸或假评分。
- 每个槽位和问题摘要都带上位置与身份，委托给同一个 `select(position, identity)`；过期身份不会选择新的声骸。
- 再次激活同一个槽位即收合。全局问题没有可靠槽位目标时，只展开计算依据，不改变选择。

## DOM 更新与可访问性

`role-register-page.js` 保留五个 `.rr-slot` 节点、唯一 `.rr-inline-analysis` 宿主与 `.rr-connector` 节点，更新内部展示内容和状态属性，不向页面追加分析面板。
新版卡片通过边框、淡背景及状态文字表达选取；连接线节点仅为兼容保留且隐藏。卡片不依赖 subgrid，程序滚动尊重 `prefers-reduced-motion`。

槽位使用原生 button，因此支持 Tab、Shift+Tab、Enter、Space；`aria-pressed`、`aria-expanded` 与 `aria-controls` 同步更新。
Selected 同时使用边框、淡背景与文字；hover 和键盘 focus 均有清楚轮廓。
Escape 或收合按钮返回当前槽位焦点；问题摘要入口展开后把焦点移到分析标题。
语言切换保持控制器状态，仅重绘 presentation，包含隐藏标签和区域 `aria-label`，不调用 adapter 或写入角色数据。

## 真实分析数据

展示位置、实体名称／ID、实例 ID、Cost、主词条、主词条及固定贡献、每条副词条的实际值、模型系数、贡献和计分原因。
缺副词条保留缺失行；不完整数据明确区分于低分。未知模型只显示已有原始数值，系数／贡献为空，不生成建议。
候选比较按钮禁用，仅说明 Phase 2，不实现候选选择或比较计算。

## 模型刷新

链数、有效 damage mode、角色 51 的额外共鸣效率与角色 62 的参考生命使用已存在评分 API 重建 view model，不修改公式。
重算后按身份重新确认选择；同一唯一 ID 移至其他位置时跟随该实例，消失或身份模糊时清除并通过三语状态通知说明。
重算不排序；`pageshow`、窗口恢复焦点和 `mcData` storage 事件会检查源记录，仅在记录变化时重建。
本次模型条件只保存在内存，不扩展存档格式，不提前实现 Phase 2 的配置草稿。

## 编辑与新增返回

- 手动角色的独立“编辑声骸”链接带 `roleid`、`costid`、`returnRegister=1` 与 `rrPosition`，不把整个槽位变成编辑链接。
- 原编辑器保存、删除或移至声骸库后，经 `editorReturn()` 生成固定的本地角色页地址；没有开放任意 return URL。
- 新版收到 `selectedPosition`／`selectedEcho` 后核对唯一实例：可靠才恢复；删除或替换身份不可识别时回到总览。处理后移除临时 URL 参数。
- 原版编辑器仍按原有明确保存／删除规则写入，本检查点只调整返回路由，没有改变评分算法。
- 空槽主操作为“加入声骸”，转入现有新增流程；特殊 `registerAdd=1` 入口绕过旧初始化的排序／缓存回写，明确新增后按新实例 ID 返回新版分析。
- 现有新增流程按原数组末尾追加，选择后方空槽不会插入空洞或移动已有声骸；返回时定位实际新增位置。导入配置的空槽则提供更新导入数据入口，不把导入角色改造成手动配置。
- 既有编辑器／新增流程仍使用原界面语言；本次三语范围为新版角色工作面。

## 存储边界

槽位选择、收合、问题导航、依据展开、模型预览和语言重绘均不写入 `mcData`。
语言手动切换仍仅写 `wuwa.ui.locale`。独立编辑器中的明确保存与新增维持原有写入行为。
浏览器 QA 页面是显式生成、显式点击的合成测试数据入口，产品页面不会加载它。

## 現行保存與返回邊界

角色／配置改名、模型設定與候選編輯沿用明確保存與 RegisterUnsaved。失敗／來源衝突保留輸入；沒有修改不多一次確認。返回地址由 RegisterNavigation 驗證，角色、槽位、實例及來源已變時安全清除失效選取，不依名稱或 DOM 順序猜測。語言切換只改顯示與偏好，不重新發送官方請求。

## 歷史保存返回證據（2026-10-08）

以下為合成存檔、隔離環境的實際操作紀錄；不是玩家帳號驗收。

### 环境与操作

使用本机独立 QA 来源 `http://localhost:8769` 的合成角色 101，Desktop 1440px，手动配置位置 03、声骸实例 602。
正式验收以该 Desktop 尺寸重新载入 `mccost.html?roleid=101&view=register` 后开始；较窄视口仍遵循既有预览开关规则，使用原版界面。

每轮均从 register view 选择位置 03，点击独立“编辑声骸”，在既有编辑器修改暴击副词条并确认词条修改。随后用户亲自点击“保存并返回”，在原生确认框确认保存，并逐轮回复“已储存并返回”。
原生确认没有被自动接受、替换或绕过。返回结果由浏览器 DOM 和独立只读存档审计页核对。

| 返回语言 | 暴击实际值 | 该词条贡献 | 单颗分数 | 总分 | 返回选取 |
| --- | --- | --- | --- | --- | --- |
| zh-TW | 8.1% | 2.98 | 9.15 | 71.68 | 位置 03 / 实例 602 |
| zh-CN | 8.7% | 3.20 | 9.37 | 71.90 | 位置 03 / 实例 602 |
| en | 9.3% | 3.42 | 9.59 | 72.12 | 位置 03 / 实例 602 |

上述三组值分别与原有评分 API 经 view model 计算的结果一致。简中总分在新版显示为 `71.9`，存档为 `71.90`，仅为既有数字格式化规则差异。

### 十项检查结果

1. 从 register view 选择已配置声骸：通过。
2. 独立编辑入口进入既有编辑器，携带角色、实例及返回位置：通过。
3. 实际修改并由用户明确保存：三轮通过。
4. 三轮返回网址均为 `mccost.html?roleid=101&view=register`；临时恢复参数按原有实现处理后移除：通过。
5. 唯一实例 602 恢复位置 03，inline analysis 自动展开且显示保存后的词条：通过。
6. 单独的 QA 故障注入将实例 602 改为 9999，再使用旧实例 602 的返回上下文载入，结果无选择、分析收合并显示配置更新通知。另将位置 03 的 ID 改成与位置 01 相同的 600，以该重复 ID 返回，亦不猜测位置。两种情形均通过；故障注入后已恢复保存完成时的 QA 快照。
7. 实际显示值、保存缓存值及既有计算入口的重算值一致：通过。
8. 返回后单次点击已选槽位即收合，单次点击另一槽位即选择该槽；分析宿主始终只有一个，未观察到重复事件触发或面板累积：通过。
9. 每轮返回的 `html.lang` 和显示文案保持该轮手动选择的 zh-TW、zh-CN、en：通过。
10. 繁中保存后建立只读审计基准，收合、再次选择、切换语言、进入编辑器及修改但未提交时，`mcData` 字节保持不变。后续两次明确保存分别观察到一次存档变更；返回后的收合／切槽没有追加变更，五颗实例顺序始终为 600、601、602、603、604：通过。

### 观察边界

- 存档审计以内容快照和跨页 storage 变更事件为依据，不宣称能统计写入相同字符串的底层 API 调用次数；1C 已有回调测试另验证初始化／取消零写入。
- 身份错误情景使用独立临时 QA 页面显式修改测试存档，不是产品操作的额外副作用，也不是真实账号数据。错误情景的修改及还原与保存副作用检查分开计数。
- 语言偏好写入仍是预期行为；本检查点检查的是角色存档 `mcData`。
- 本轮未发现需要修正的产品问题。仅新增本记录，尚未开展 1D 真数据验收。

## 角色工作台装备卡片改版（2026-10-14）

以 `docs/role-workspace-redesign.md` 为当前布局和验收说明。桌面为 260px 角色栏与主工作区，五件等宽装备卡片；手机为单栏摘要与 132px 原生横向卡片。配置与危险操作收进明确的管理入口，不改变名称或保存语义。
