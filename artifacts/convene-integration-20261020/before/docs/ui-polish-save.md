## 保存范围与故障原因

名称由既有 `RegisterMetadata` 的角色名称映射保存，与 mcData 装备数据分离；只是当前角色配置的名称，不是多套声骸。

任务前真实浏览器复现见 `save-before.json`：提交带空格的名称后，存储已保存去空格的名称，但输入框保留旧文本，成功提示仅写入当时 DOM，语言切换触发重绘后消失。因此不能将其描述为核心写入失效。另一个边界是元数据读取失败时整个名称操作区被跳过，用户看不到原因。

修复在 page 层保留提示状态、同步成功返回的名称并更新标题；校验失败、配额失败、来源冲突及读取失败都有反馈。损坏元数据不自动重置；来源冲突首次不覆盖，用户明确重试后才按最新版本提交。新测试覆盖刷新、角色往返、语言重绘、Enter 提交、失败重试及损坏数据保护。
