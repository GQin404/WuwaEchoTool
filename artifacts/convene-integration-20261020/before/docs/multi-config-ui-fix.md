# 多配置管理、侧栏与配置比较 UI 修正

日期：2026-10-20。基于任务开始时的干净工作目录（HEAD见交付BASELINE.json），只整理现有多配置界面与显示，不重新开发配置系统。没有改评分公式、官方导入保留／覆盖规则或共享装备规则，没有Git提交／推送。

## 三个实际根因

1. `multi-config-browser.js` 的专属 `open()` 无条件追加 `.rr-dialog-actions` 底部关闭栏；`multi-config.css` 又将其设为 `position:sticky;bottom:0`。管理和比较均出现长背景条及内容遮挡。改为专属顶部标题／关闭与独立滚动体，其他需要确认／下载的弹窗保留原操作区。
2. `role-register-page.js` 的旧 `decorate()` 继续在 `rr-role-management` 折叠区注入配置名表单、输入恢复guard和保存事件，与新配置管理重复；删除角色也在该折叠区。已删除侧栏表单、专属状态与事件，并从渲染器移除折叠容器。保存的真实比较方案与官方角色更新入口保留，不显示空方案说明。
3. `RoleViewModel` 标准化后把 `echo.name` 移到 `echo.legacy.name`，比较却仍读已删除字段；新版catalog缺少翻译时便显示键值。现在读取标准化原名及完整catalog回退，拒绝未解析键值；标准化阶段也将缺失／键值形式的旧name回退为catalog名。没有硬编码截图四个名称。

## 最终界面与行为

- 配置管理每行显示名称、当前／默认状态和装备数；当前配置不显示切换，默认配置不重复提供设默认。原生details内联管理包含重命名、设默认和删除；菜单占整行，打开只改变高度，不改变列表宽度或创建会被裁切的浮层。
- 重命名在弹窗内保存并立即更新列表、侧栏选择器及摘要；不需要页面刷新。最后一套禁删，删除确认及当前配置切换保护保留。顶部关闭、Escape、遮罩、原生键盘焦点限制与关闭返回焦点均保留。
- 侧栏仅保留当前配置选择器、新建／管理、评分设置、分享，以及必要的已存方案／官方更新。删除角色直接作为末尾危险操作显示；手机沿原响应式工作台顺序显示在页面管理区末尾，不改变五卡横向浏览及原位分析。
- 比较按槽位，不按Cost匹配；每侧显示真实名、Cost、可解析套装、主属性／数值、评分。区分同实体、不同实体、A空、B空和两侧空。桌面等宽双栏，手机上下单栏。
- 每次选择比较对象都从当前存档建立独立投影并调用原标准化／评分入口，没有复用另一配置的缓存。完整配置显示原总分；未满套明确显示原模型的“已知贡献”，差异也标为已知贡献差异，避免把部分值冒充完整总分。
- 雷达五轴确实代表五个声骸槽位，现用三语“位置1～5／Slot1～5”。沿用RegisterShare.radarData的五槽原始贡献及共同上限；不编造维度、不改公式，不足／无效数据不画完整填充。

## 删除角色保护接线

检查发现Register确认写入原先只清理名称，没有把已有的`resetRoles`选项传入共享提交。现在v2确认沿原`CharacterCore.removeRole`移除角色，并交由既有`saveDataToCache`／`MultiConfig.commit`日志事务清理该角色草稿、采纳与名称、会话缓存。声骸实体全量保留，其他角色及其共享引用保留；旧格式写入分支保持原样。没有重设计删除或共享核心。
