## 十项检查结果

1. 从 register view 选择已配置声骸：通过。
2. 独立编辑入口进入既有编辑器，携带角色、实例及返回位置：通过。
3. 实际修改并由用户明确保存：三轮通过。
4. 三轮返回网址均为 `mccost.html?roleid=101&view=register`；临时恢复参数按原有实现处理后移除：通过。
5. 唯一实例 602 恢复位置 03，inline analysis 自动展开且显示保存后的词条：通过。
6. 单独的 QA 故障注入将实例 602 改为 9999，再使用旧实例 602 的返回上下文载入，结果无选择、分析收合并显示配置更新通知。另将位置 03 的 ID 改成与位置 01 相同的 600，以该重复 ID 返回，亦不猜测位置。两种情形均通过；故障注入后已恢复保存完成时的 QA 快照。
7. 实际显示值、保存缓存值及既有计算入口的重算值一致：通过。
8. 返回后单次点击已选槽位即收合，单次点击另一槽位即选择该槽；分析宿主始终只有一个，未观察到重复事件触发或面板累积：通过。

10. 繁中保存后建立只读审计基准，收合、再次选择、切换语言、进入编辑器及修改但未提交时，`mcData` 字节保持不变。后续两次明确保存分别观察到一次存档变更；返回后的收合／切槽没有追加变更，五颗实例顺序始终为 600、601、602、603、604：通过。
