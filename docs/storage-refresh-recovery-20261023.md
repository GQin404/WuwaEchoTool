# 刷新时的存档兼容恢复

本轮针对用户录像中的「无法安全迁移或恢复资料」进行相容修正。没有取得该用户的原始存档，尚未确认录像的具体根因；以下为已复现并通过验证的恢复范围，不保证所有同文案故障都能自动恢复。

## 自动恢复范围

- 新版 `loadoutVersion:2` 的 `configurations` 与 `echoes` 仍有效，但旧版投影 `role.costList` 或 `unusedEchoes` 缺失、类型错误或过期：先从实体和当前配置重建，再进行核心校验。其他配置、实体身份、伤害条件和词条保留。
- 单配置缺少活动／默认配置指针时，可以唯一确定配置；缺失配置名称、来源、归属与时间元数据时补默认值。已有短槽位数组补到五槽；不会截断超过五槽的数组。
- 单配置缺少 `settings` 时，从该角色的现有投影条件恢复；多配置缺少条件时拒绝猜测。
- 旧版缺少装备列表字段或空声骸库字段时补空列表后走原有迁移。显式 `costList:null` 的旧版角色不推测为空。
- `mcData` 不存在或为 JSON `null` 时初始化空存档。

重复／缺失角色 ID、重复实体 ID、缺失实体库、多个配置无法确定活动项、未知版本及损坏 JSON 均不会通过删除、合并、重编身份或清空的方式自动恢复。

## 原始资料与失败保护

`CharacterCore.initialize` 是 Register 共用启动入口。修复或迁移现有存档前，先将核心、草稿、采纳、名称、声骸元数据及事务日志的原始字符串保存在 `wuwa.multiconfig.compatibilityBackups.v1`。相同快照不重复追加；正常新版存档在刷新时不重复写入。备份失败则停止本次修改；核心提交继续使用既有事务和来源冲突检查。既有事务日志仍先按原有机制恢复。

不能安全恢复时，页面暂停编辑，旧核心保存入口也会拒绝写入；顶部提供三语言「下载原始数据备份」。该下载不依赖 JSON 解析成功，不经过数据清洗，且只读取白名单存档键，不导出登录凭证。此原始诊断文件不能直接当作普通备份导入。

发布后各入口使用 `20261023-recovery1` 版本参数加载修改过的脚本和提示样式；`/js/*` 要求缓存重新验证。用户无需手动编辑 Local Storage 或清除网站数据，进入更新入口并刷新即可触发以上兼容流程。
