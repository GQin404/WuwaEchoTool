# 1D｜Representative Fixture Validation

日期：2026-10-08。

结论：**Engineering Complete / Real-data Acceptance Pending**。

用户确认当前没有真实手动角色或真实导入角色存档，因此将本检查点改为代表性合成数据验收。本记录不代表真实账号验收，不验证线上导入接口、账号权限或真实上游数据兼容性。后续以 1D.5 Real-data Acceptance 补充实际存档交叉验证，不重新设计架构。

## 数据与方法

- 新增 `tests/register-fixture-acceptance.test.cjs`：280 组手动／导入配对配置，覆盖角色模型 1、49、51、52、53、57–63，0–6 共鸣链、各模型支持的 damage mode、extraEnergy 0/200、referenceHealth 45000。
- 每组五槽故意采用 Cost 1/4/3/3/1 的非排序顺序。主词条分别为攻击、暴击、共鸣效率、属性伤害、生命；副词条包括双暴、效率、技能伤害和零权重防御。缓存评分故意设为 999。
- 手动角色使用数字角色 ID、字符串声骸目录 ID；导入角色使用字符串角色 ID、独立上游声骸目录 ID 和图片 URL，不把两种目录 ID 假定为同一体系。图片 URL 是字段透传测试，不执行外网资源可用性验证。
- 直接加载原版 `scoreAdjust()` 和导入页 `randerCostList()`，在副本上执行。DOM 使用查询桩，真实 localStorage 写入被禁止；旧页保存调用另行记录。
- 依 costId 对照单颗贡献，不按旧页排序后的行号配对。已舍入的分数使用 0.000001 浮点容差比较，整套总分按原版两位小数规则比对。
- 其他边界、选择恢复和编辑行为复用既有合成测试；实际浏览器保存确认复用已通过的 1C.5 人工操作记录，没有重复要求用户保存。

## 原版差异分类

1. **旧页缓存值**：普通导入模型直接显示 `sumScores` / `totalScore` 缓存，合成的 999 会被原版保留。register 使用评分 API 重算；给旧页填入独立的原版手动重算结果后，双方单颗及总分一致。不能将原版缓存显示当作计算真值。
2. **旧页排序／副作用**：手动 scoreAdjust 和导入渲染按 Cost 原位排序；手动总分改变时保存，特定导入模型渲染时保存。本次只在副本上记录这些行为。register 输入未变，也未因原版排序而改变位置。
3. **显示语义**：旧页缺副词条可能显示 0.00；新版以 incomplete 和未知整套总分表达，保留已知小计。这是已确认的数据完整度语义，不是公式差异。
4. **数值格式**：例如 71.90 与 71.9 是 formatter 差异，原始 number 和计算不变。
5. **正规化／API／公式**：本矩阵未发现导致评分不一致的问题，未修改产品计算代码。

本轮在 1440px 浏览器复核英文选中位置 03 的完整工作面：左侧角色身份、五槽共同基线、共同尺度、连接线与单一原位分析仍保留，未引入卡片网格。浏览器读数为单颗 9.59、总分 72.12、已知小计 75.59、整套校正 -3.47，与 1C.5 最终 fixture 相符。

三语 UI key 完整不代表全游戏实体名称目录已经完整翻译。未收录的上游声骸目录 ID 仍使用既有本地化 ID 标签，保留原始身份／图片字段，不伪装成另一个已知声骸。上游真实 ID、名称、图片与套装的覆盖情况需要在 1D.5 使用实际记录核查。合成 URL 透传测试不能证明真实图片一定可加载。
